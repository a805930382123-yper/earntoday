## 调度与取消

`src/autonomous/frequency.ts` 定义当前随机等待范围：眨眼/双耳 **30–45 秒**，哈欠/尾尖 **60–180 秒（1–3 分钟）**。这是用户本地体验确认后的频率调整，动作素材与动作本身的播放时长不变。`scheduler.ts` 继续维护两档独立截止时间。最多一个等待定时任务；播放期间由 `playback.ts` 维护一个必要的换帧定时任务，没有常驻逐帧循环。工资刷新不在调度 effect 的依赖中，快速动作结束不会移动尚未到期的慢速截止时间。同刻冲突或播放期间到期的动作丢弃，不排队。

启动、恢复可见、重新满足条件及用户活动后重新随机等待；定时回调迟到超过 2500 ms 或时钟回退时丢弃旧截止时间。播放器也有超时和播放序号校验。当前动作结束或取消只撤下临时层，底图由最新 React 属性提供，不缓存并恢复旧主题图片。

仅开关开启、系统不要求减少动态效果、原生窗口可见且未最小化、普通工作状态、隐私可见、精确底图匹配、素材解码完成且没有互动/拖动/积累投放/完成反馈时可播放。设置和主题页面卸载桌宠播放器。只按当前主题、当前实际底图准备资源；失败动作本会话跳过，保留正确静态图，不无限重试。

原生显示状态复用 `main-visibility` 链路，订阅后初始查询真实 `is_visible && !is_minimized`，原生尺寸/最小化事件刷新；没有高频原生查询，也不以焦点作为条件。`document.hidden` 不单独决定自主动作资格。

点击按下立即撤下自主帧，现有点击互动照常接管。角色与卡片拖动使用原有原生 `startDragging`，在原生移动循环结束前阻止自主播放。主题、工作状态、模式、显示方式、积累阶段、底图或可见性变化均取消旧动作。趣味积累少女半满 `character-half`、满格 `character-full` 与普通底稿不匹配，直接避让；咪宝仍使用普通工作底稿的积累阶段可在反馈结束后播放。午休、休息日、下班、隐私图及点击专属表情不被覆盖。

## 本地复现

在项目根目录运行 `npm test`、`npm run build`；Rust 运行 `cargo test --lib --features isolated-test`。浏览器测试运行 `node tools/run-autonomous-check.cjs <含 playwright 的 node_modules 绝对目录>`，脚本自行启动并清理 5178 开发服务。

需要手动检查正式原生窗口时使用通常的本地开发流程，选择工作状态、显示隐私可见，进入设置开关保存后等待 30–45 秒观察第一次眨眼/双耳；慢动作等待 1–3 分钟。点击、拖动、切换主题/模式/隐私、进入设置或隐藏应立即打断，恢复显示不立即补播。半满/满格少女积累表情应始终保留。

Windows 自动检查必须先构建 `cargo build --features isolated-test`，再运行 `node tools/verify-autonomous-native.mjs`。脚本拒绝普通二进制，只创建系统临时目录下有标记的合成配置，不使用正式用户配置；短时间性能采样也不应解读成长期性能保证。

## 本地体验确认后的频率调整

用户确认原本地 EXE 的自主动画正常后，将快动作等待由 45–90 秒调整为 30–45 秒，慢动作等待由 8–15 分钟调整为 1–3 分钟。只调整等待范围，继续使用同一调度器的冲突丢弃、取消和独立截止时间规则，不改变动作时长或专属表情避让。

`frequency-test.log` 记录 46 项测试通过；`frequency-browser-test.log` 记录七个正式组件样本及全部行为检查通过，其中受控随机数验证新的最短等待以及 90 秒慢动作截止时间不会被 33.75 秒的快动作反复推迟。恢复显示仍重新随机等待。`frequency-exe-build.log` 记录本地正式 EXE 重建过程，版本、更新配置和原用户设置继续保留，不发布 GitHub Release。
