# B0-02 / B0-04：隐藏与恢复

范围：现有单原生窗口的无损恢复、全局快捷键、前端可见性同步。工资计算、用户配置路径、应用身份、安装范围与更新签名保持既有设计。

## 用户操作

- `Ctrl+Shift+H` 切换隐藏/显示，默认启用；设置页底部「隐藏与恢复」可停用，注册失败时可重试。
- 托盘左键及「显示 / 恢复窗口」只显示并聚焦当前窗口，不导航、不调整大小、不重新定位。
- 当前是工资设置或主题选择页时，隐藏和恢复不卸载设置组件，草稿、校验提示、子页面、滚动位置继续保留。
- 托盘「设置」在设置已打开时只恢复当前页面；首次打开时仍使用现有 400×600 布局。
- 保存设置或明确点击「关闭设置」仍返回小组件，按原有完整/迷你模式恢复尺寸和位置。未保存草稿不跨退出应用或明确关闭设置保存。
- 快捷键占用不会导致应用退出。界面显示注册失败，托盘仍能恢复窗口；释放冲突后点击重试。

此改动只在当前源码及重新构建的程序中生效，既有已发布 v0.3.0 安装包不会因此自动改变。

## 实现约定

原生可见性统一通过 `visibility.rs` 的显示/隐藏入口发布 `main-visibility`（visible + revision）。前端先订阅后读取初始快照，拒绝旧 revision，兼容桥接初始化重试；同时结合网页 visibilitychange/pageshow。隐藏时停用可见时钟、取消互动/积累反馈，并禁用 CSS 动画与过渡；恢复首帧使用当前时间，作用域变化阻止旧反馈及下班庆祝补播。正常可见状态跨过积累节点仍会播放一次。

快捷键只处理 Pressed，并抑制长按重复；Released 只解除按键锁。注册仅在 Rust 中执行，不向 WebView 开放任意快捷键注册权限。

配置只新增布尔字段 `shortcutEnabled`，缺失默认 true、显式 false 保留。使用现有增量保存与备份路径，不重置工资或未知字段。首次使用、尚未保存工资或主题时，开关先保存在内存，随首次有效设置保存。保存失败会撤销原生注册变更；恢复备份后重新应用恢复出的快捷键偏好。

## 验证方法

```powershell
npm.cmd test
npm.cmd run build
cargo test --locked --lib --manifest-path src-tauri/Cargo.toml
```

网页测试：启动本机 Vite 5178 服务，使用已有 Playwright 环境运行 `node tools/verify-visibility.cjs <含playwright的node_modules目录>`。使用模拟桥接和模拟时钟，覆盖两种主题×完整/迷你、设置及主题子页面草稿、开关、原生事件独立生效、互动取消、正常积累对照、隐藏跨午休/下班、旧事件、减少动态效果。

Windows 原生测试必须显式构建隔离程序：

```powershell
npm.cmd run build
cargo build --locked --manifest-path src-tauri/Cargo.toml --features isolated-test
node tools/verify-visibility-native.mjs
```

`isolated-test` 在普通构建中关闭，普通程序不接受测试数据目录环境变量。测试程序要求 OS 临时目录内存在专用标记文件，缺失即拒绝启动。脚本还会拒绝普通程序；工资和偏好均使用人工数据。测试只结束自己启动的进程，保留临时目录以便检查，不运行安装器、不读取真实薪资配置。隔离程序仅供测试，不作为日常程序或安装包分发。

本轮原生冒烟检查收窄为三项：快捷键按下/松开及长按只切换一次；设置/主题子页恢复后草稿与窗口几何保留；注册冲突时托盘仍能恢复、释放冲突后可重试。网页已通过的两主题×两模式不在原生层重复遍历，也不执行损坏配置、备份恢复及重启等扩展用例。

检查使用实际 Windows 注册、合成固定按键、WM_CLOSE、真实窗口矩形，并向测试进程的托盘回调窗口发送左键消息。后者验证托盘回调链路，不等于人工点击 Explorer 托盘。第二个隔离实例用于制造冲突，不代表已解决 B0-05 单实例问题。
